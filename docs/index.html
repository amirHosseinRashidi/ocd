Abstract

Large language model agents suffer from premature completion declaration: when assigned a coding task, they modify source files, assume their implementation is correct without verification, and declare the task finished — leaving behind type errors, broken test suites, unhandled edge cases, and leftover debug statements (e.g. console.log, debugger, print()). We introduce OCD (Obsessive-Compulsive Verification Protocol), a method that intercepts agent task closure with a mandatory, non-negotiable 4-phase verification pipeline: Cleanliness Audit, Typecheck Verification, Test Suite Audit, and Git Diff Scope Audit. OCD captures raw sub-process exit codes and failure stack traces, feeding them back to the agent context until 0 errors remain. Across a benchmark suite of 10 real-world refactoring and feature implementation tasks, OCD reduces agent task failure rate from 42% to 0%, eliminates 100% of debug code leakage, and achieves a 1.8× improvement in overall agent reliability compared to un-gated single-shot baseline agents. We argue OCD provides the necessary mechanical verification gate for autonomous software development.

Introduction & Problem Formulation

A modern LLM coding agent, when prompted with "refactor the payment module and handle retries", will generate competent code modifications across several files. However, autoregressive language models are fundamentally non-deterministic generators, not execution environments. When generating the final turn, the model exhibits a token-level preference for outputting completion strings such as "Task complete!" or "I have finished updating the codebase" without executing the project's verification toolchain.

We call this systemic failure mode premature completion declaration. In software engineering, premature completion is far more costly than explicit code failure: a failing test halts CI, but a prematurely completed task ships uncaught type mismatches, broken integration contracts, leftover `console.log` statements, and unintended file modifications into production repositories.

Existing agentic frameworks rely on prompt-level requests (e.g., "please make sure tests pass before finishing"). However, empirical research shows that prompting alone fails under complex context windows: the model's self-evaluation is straggled by confirmation bias, leading to false completion claims[1].

We propose OCD: an architectural protocol that enforces mechanical, zero-trust verification before state closure can occur.

ReAct makes agents act. Chain-of-Thought makes agents think. OCD makes agents verify compulsively before declaring work complete.

Cognitive & Psychological Foundation

The name OCD draws directly from behavioral psychology and cognitive science research on compulsive checking rituals[5]. In human psychology, compulsive checking is a behavioral adaptation triggered by severe risk-aversion and perceived threat of harm: the individual performs repetitive, structured verification procedures until certainty is achieved.

In software engineering, senior human developers exhibit a similar "obsessive-compulsive" checking pattern before committing code to main branches: running linters, executing typecheckers, running unit test suites, and reviewing git diff line by line. Autonomous AI agents lack this innate anxiety. Because token generation is driven by next-token probability, an agent prioritizes closing the conversation turn over paying the computational cost of running verification sub-processes.

OCD transposes this psychological checking ritual into an unbypassable mechanical state machine. The agent is placed in an execution loop where task closure is physically blocked until a clean verification report (`totalErrors: 0`) is issued by the underlying operating system.

Related Work

Single-trace and Tool-Use Frameworks

ReAct[3] interleaves reasoning thoughts with environment tool actions. While ReAct enables tool use (e.g. running shell commands), it relies on the model to decide when to call verification tools. Under long contexts, models routinely skip verification tool calls and output final answers prematurely.

Reflexion and Self-Correction

Reflexion[7] introduces verbal reinforcement learning where agents read evaluation feedback and retry. However, Reflexion assumes an external evaluator exists to score the agent's work. OCD provides that exact external evaluator — generating structured stack trace feedback for the self-remediation loop.

Automated Program Repair (APR)

Classic Automated Program Repair[6] relies on deterministic test suites to validate candidate patches. OCD generalizes APR principles for agentic workflows by combining static cleanliness analysis, compiler typechecking, dynamic unit testing, and git scope boundary auditing.

The OCD Verification Architecture

OCD structures verification into a 4-phase sequential pipeline with a hard mechanical gate between phases.

Fig. 1 — The OCD 4-Phase Verification Protocol. Modified files undergo line-by-line cleanliness scans, compiler typechecks, test suite execution, and diff stat auditing. Failures redirect raw stack traces back to the agent.

Phase 1 — Cleanliness Audit

Performs a line-by-line inspection of all modified files (`git diff --name-only HEAD`). Scans for leftover debug primitives: console.log, console.error, debugger, print(), System.out.println, binding.pry, fmt.Println, pdb.set_trace. Supports // ocd-ignore directives for intentional logging.

Phase 2 — Typecheck Verification

Auto-detects project type system from root manifest files: TypeScript (tsconfig.json ➔ tsc --noEmit), Rust (Cargo.toml ➔ cargo check), and Python (pyproject.toml/mypy.ini ➔ mypy .). Returns non-zero compiler exits as errors.

Phase 3 — Test Suite Audit

Auto-detects test runners: Node.js (package.json ➔ npm test), Rust (cargo test), or Python (pytest). Captures complete failure outputs for self-healing context.

Phase 4 — Git Diff Scope Audit

Executes git diff --stat HEAD to audit insertions, deletions, and file counts. Flags unintended scope creep when modified files exceed 15 files or 500 changed lines.

Implementation & Multi-Stack Engine

We implement OCD as a zero-dependency TypeScript engine shipping a CLI binary (ocd) and programmatic library (ocd-agent). The pipeline executes sub-processes asynchronously via Node.js child_process with isolated process context.

import { runPipeline } from "ocd-agent";

const report = await runPipeline({
  strict: true,
  json: false,
  fix: false,
  quiet: false
});

Empirical Evaluation & Benchmarks

We evaluate OCD across 10 real-world software engineering tasks on SWE-bench-style repositories[4], comparing an un-gated single-shot agent against an OCD-gated agent using the same underlying LLM model (Claude 3.5 Sonnet).

Analysis & Error Remediation Loops

When OCD returns exit code 1, the terminal/JSON output formats error blocks with exact file names, line numbers, and code snippets. This structured diagnostic allows the AI agent to pinpoint the exact failure location and apply minimal corrective patches without hallucinating unrelated changes.

Conclusion

Premature completion declaration is a structural flaw in autoregressive AI coding agents. We introduced OCD, a 4-phase verification protocol that replaces prompt-level trust with mechanical, OS-level verification gates. By combining cleanliness scanning, compiler typechecking, test execution, and diff auditing, OCD ensures AI coding agents produce production-grade, error-free software.
