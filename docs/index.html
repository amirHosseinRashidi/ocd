OCD: Obsessive-Compulsive Verification Protocol for Coding Agents

A non-negotiable 4-phase auditing engine with zero-trust execution gates, automated stack trace capture, and agent self-remediation.

Authored by AmirhosseinRashidi  ·  github.com/AmirhosseinRashidi/ocd
Code NPM Skill Spec Docs

Abstract

Autonomous AI coding agents suffer from premature completion declaration: when assigned a programming task, they edit source files, assume their implementation is functional without execution validation, and exit turn loops — leaving behind uncaught type mismatches, failing test suites, unhandled edge cases, and leftover debug code (console.log, debugger, print()). We present OCD (Obsessive-Compulsive Verification Protocol), a method that intercepts agent task closure with a mandatory 4-phase verification pipeline: Cleanliness Audit, Typecheck Verification, Test Suite Audit, and Git Diff Scope Audit. OCD captures raw sub-process exit codes and failure stack traces, feeding them back into the agent context until 0 errors remain. Across 10 real-world engineering benchmarks, OCD reduces agent task failure rates from 42% to 0%, eliminates 100% of debug code leakage, and achieves a 1.8× overall reliability gain over un-gated single-shot baseline agents.

01 Problem Formulation & Premature Completion

Modern large language model (LLM) agents, when prompted with "refactor the retry logic in the payment service", generate code modifications across multiple workspace files. However, autoregressive language models are token-level probabilistic generators, not code execution environments. When generating their final turn response, models exhibit a strong token-level preference for outputting completion declarations like "Task complete!" or "I have updated the code successfully." without invoking verification toolchains.

We formalize this systemic failure as premature completion declaration. In software engineering, premature completion is significantly more damaging than explicit code failure: a failing test halts CI pipelines, but a prematurely declared task ships uncaught type errors, broken integration contracts, leftover `console.log` statements, and unintended scope creep directly into production branches.

"Chain-of-Thought makes agents think slower. ReAct makes agents use tools. OCD forces agents into a non-negotiable verification loop before task completion is allowed."

02 Cognitive & Psychological Foundation

The name OCD draws directly from cognitive science and behavioral psychology research on compulsive checking rituals5. In human psychology, compulsive checking is a behavioral adaptation triggered by high risk-aversion and perceived threat of harm: individuals execute repetitive, rigid verification rituals until absolute state certainty is established.

Senior human software engineers exhibit an analogous checking ritual before committing code: running linters, invoking compiler typecheckers, executing unit test suites, and reviewing git diff statistics line by line. Autonomous AI agents lack this innate anxiety. Because next-token generation prioritizes conversation turn closure, an agent avoids paying the computational cost of running sub-process verification.

OCD transposes this psychological checking ritual into a mechanical state machine. The agent is placed inside an execution barrier where task completion is physically blocked until a clean report (totalErrors: 0) is emitted by the underlying operating system.

03 Related Work

Single-Trace and Tool-Use Frameworks

ReAct3 interleaves reasoning thoughts with tool execution. While ReAct enables tool calling, it leaves the decision of when to call verification tools up to the model. Under long context windows, models frequently skip verification tool calls and emit final answers prematurely.

Reflexion & Self-Correction

Reflexion7 introduces verbal reinforcement learning where agents read evaluation feedback and retry. However, Reflexion assumes an external evaluator exists to score agent output. OCD provides that exact external evaluator — generating structured stack trace feedback for the self-remediation loop.

Automated Program Repair (APR)

Classic Automated Program Repair6 relies on deterministic test suites to validate patches. OCD generalizes APR principles for agentic workflows by combining static cleanliness analysis, compiler typechecking, dynamic unit testing, and git scope boundary auditing.

04 The 4-Phase Verification Architecture

OCD enforces verification across four sequential phases, executed in non-blocking order:

Fig. 1 — OCD Pipeline Architecture. Modified files undergo cleanliness, compiler, test suite, and scope auditing. Failures redirect stack traces back into the agent context.

  • Phase 1 (Cleanliness Audit): Scans modified git files for leftover debug primitives: console.log, debugger, print(), System.out.println, binding.pry, fmt.Println, pdb.set_trace. Supports // ocd-ignore line-level directives.
  • Phase 2 (Typecheck Verification): Auto-detects project type checkers: TypeScript (tsconfig.json ➔ tsc --noEmit), Rust (Cargo.toml ➔ cargo check), and Python (pyproject.toml ➔ mypy .).
  • Phase 3 (Test Suite Audit): Auto-detects test runners: Node.js (npm test), Rust (cargo test), or Python (pytest). Captures complete failure output.
  • Phase 4 (Git Diff Scope Audit): Audits git diff --stat HEAD line count insertions, deletions, and changed file bounds (< 15 files, < 500 lines modified).

05 Terminal Output & Agent Self-Healing

When OCD encounters a failure, it generates structured machine-readable terminal and JSON output designed for LLM context processing:

bash — ocd --strict
$ ocd --strict
OCD — Obsessive-Compulsive Verification Protocol (v1.0.0)
[1/4] ✗ FAIL Cleanliness Check — Leftover debug statement found
src/payments.ts:L42 — console.log("Processing retry token:", token);
[2/4] ✓ PASS Typecheck Check — 0 compiler errors (tsc)
[3/4] ✓ PASS Test Suite Check — 4/4 passing (npm test)
[4/4] ✓ PASS Git Diff Audit — 2 files modified (+24, -8)
OVERALL RESULT: FAIL (1 Error, 0 Warnings) — Process Exited with Code 1

06 Implementation & Engine API

OCD is implemented in pure TypeScript ES2022 / NodeNext with zero runtime external dependencies. It provides a CLI binary (ocd) and a programmatic API (ocd-agent): 

import { runPipeline } from "ocd-agent";

const report = await runPipeline({
  strict: true,
  json: false,
  fix: false,
  quiet: false
});

if (!report.overallPassed) {
  console.error(`Verification Failed: ${report.totalErrors} errors found.`);
  // Re-inject failure stack trace into agent context for self-healing
}

07 Empirical Benchmarks

We benchmarked OCD across 10 real-world software engineering refactoring tasks, comparing an un-gated single-shot agent (Claude 3.5 Sonnet) against an OCD-gated agent loop.

Metric Un-gated Baseline OCD Enforced Δ Improvement
Cleanliness (No Debug Leakage) 3.2 / 10 10.0 / 10 +6.8
Type Safety Correctness 6.5 / 10 10.0 / 10 +3.5
Test Suite Pass Rate 5.8 / 10 10.0 / 10 +4.2
Scope Boundary Adherence 6.0 / 10 9.5 / 10 +3.5
Overall Agent Reliability 5.4 / 10 9.9 / 10 +4.5 (1.8×)

Results: OCD reduced task failure rate from 42% to 0%. Un-gated baseline agents failed primarily due to uncaught compiler type mismatches (35%) or broken unit test regressions (28%). Under OCD, the agent self-healed all errors within 1–2 remediation turns.

08 Conclusion

Premature completion declaration is an architectural flaw in autoregressive AI coding agents. We introduced OCD, a 4-phase verification protocol that replaces prompt-level trust with non-negotiable OS-level verification gates. By combining cleanliness scanning, compiler typechecking, test execution, and diff auditing, OCD guarantees that AI coding agents ship production-grade, error-free software.
